# Context

Phase §3 (02.1) of prompt_evo_cycle2.md. Read-only AWS Glue metadata connector. Lives in `connectors/aws/` behind the `[aws]` optional extra — the core must remain installable and fully functional without boto3.

# Acceptance Criteria

- `connectors/aws/sessions.py`: builds boto3 sessions via the standard credential chain — AWS profile, env vars, IAM roles, SSO, optional AssumeRole (authorized only), configurable region. No custom credential storage, no prompting for keys.
- `connectors/aws/glue.py`: `GlueConnector` implementing `get_job`, `get_jobs`, `get_job_run`, `get_job_runs` returning typed domain models (internal, not public contracts): job metadata (name, glue version, command, default args **sanitized**, connections, role, worker type/count, capacity, timeout, execution class, security configuration) and run metadata (run id, status, attempt, started/completed, execution time, error message, DPUSeconds, log group, sanitized args, predecessors when requested).
- Pagination (complete or bounded), temporal windows, retry with backoff + jitter on throttling, cancellation support.
- Error taxonomy → structured `SentinelError` codes: access_denied, not_found, invalid_input, throttling, expired_token, wrong_region, missing_profile, no_credentials, timeout, transient — each with a PT-BR next-step hint, never exposing secret material.
- Read-only enforcement: explicit allowlist constant of permitted API actions; no mutable Glue calls (StartJobRun/StopJobRun/UpdateJob…) exist in the connector — test asserts the allowlist and that no mutating method is called even via getattr tricks.
- `docs/guides/aws-glue-connector.md`: reference least-privilege IAM policy (glue:GetJob*, glue:GetJobRun* etc., no mutating actions), adjustable per environment; documents that no permissions are auto-granted.
- All secret-bearing fields (connection strings, args like passwords/tokens) pass through `sanitize_evidence_excerpt` before leaving the connector.
- Tests use botocore `Stubber`: pagination, throttling→retry, credentials missing, AccessDenied, incomplete fields, failed/long/cancelled runs, missing optional fields, argument sanitization. Zero tests require a real AWS account.
