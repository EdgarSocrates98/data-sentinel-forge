# Acceptance Criteria

- Join recognition: INNER/LEFT/RIGHT/FULL/CROSS/SEMI/ANTI, multi-key joins, expression joins, inequality joins — extracted from SQLGlot AST and/or plan operators.
- Cardinality risk model representing exactly the prompt's shape: input cardinalities, join keys, uniqueness state (known/unknown/violated-with-evidence), estimated output or "unavailable", risk classification, missing-evidence list, recommended statistics to collect. **Never** derives real output cardinality from total row counts alone.
- Duplicated-key reasoning: when evidence shows both sides may hold multiple rows per key, classify many-to-many expansion risk, explain the mechanism, suggest verification — explicitly warns that deduplication can change functional results and never auto-suggests applying it.
- Join optimization advisor emits recommendations each carrying: pré-condições, evidências, risco de alterar semântica, potencial benefício (hypothesis, labeled as such), método de validação, rollback — evaluating column selection, filters, join type, statistics, broadcast, distribution, partitioning, intermediate materialization, aggregation pushdown, adaptive optimizations.
- Shuffle risk assessment combining join strategy + exchange operators + volume/stats/partitions/distribution/runtime metrics when present; absent inputs degrade the confidence, they do not yield fabricated byte estimates.
- Skew detection split into **suspected skew** (pattern/statistics inference) vs **observed skew** (operational evidence of unequal task durations/distribution) — findings name which category; a stage-skew metric alone never claims to identify the unbalanced key.
- High-volume conceptual fixtures built from synthetic metadata/samples (A:230M, B:73M, C:230M, D:250M rows as declared statistics — NOT real tables): variations covering unique keys, duplicated keys, many-to-many, high/low selectivity, skew, selective predicates, missing statistics, wrong statistics.
