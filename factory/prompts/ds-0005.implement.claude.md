# Context

Phase 01.3: an extensible Analyzer protocol that declares supported formats/platforms, validates input, returns structured Findings + Evidence, and declares limitations. First implementation: deterministic Spark/Glue log analyzer over local artifacts — real diagnosis, no mocks.

# Acceptance Criteria

- `analyzers/protocol.py` (or `base.py`): abstract protocol/ABC — `analyzer_id`, `version`, `supported_source_types`, `supported_platforms`, `validate_input()`, `analyze() -> AnalysisResult`, `capabilities() -> CapabilityManifest`, `limitations` property. AnalysisResult carries findings, evidences, limitations, analyzer metadata.
- `analyzers/registry.py`: register/discover analyzers, lookup by source_type; duplicate registration rejected.
- `SparkGlueLogAnalyzer` in `analyzers/spark/` with a documented, unit-testable **pattern library** covering at minimum: OutOfMemoryError (driver/executor), executor lost/task retry exhaustion, disk spill warnings, SparkException failures, AWS permission denied / AccessDenied (Glue, S3, Lake Formation flavors), Iceberg table/catalog errors, job timeout, Python/Scala worker failures. Each pattern: category, severity, title, rationale, suggested actions, verification steps.
- Analysis produces `Finding` + linked `Evidence` objects (sanitized excerpts via ds-0004 helpers, with source line references) mapped onto ds-0002 contracts.
- Unmatched/insufficient logs yield a top-level UNKNOWN/insufficient-evidence result stating what was analyzed and what additional artifacts would help — never a fabricated diagnosis.
- Findings distinguish CONFIRMED (pattern matched unambiguous error) vs PROBABLE/POSSIBLE (partial signals) per §2.1 — the mapping rule documented in code/ADR.
- `fixtures/` contains realistic synthetic Glue/Spark log samples per covered class (including a mixed-signal log and an unrecognized log).
- Tests: every pattern class detected on its fixture, evidence linked and sanitized, unknown → UNKNOWN, oversized/malformed input handled via ds-0004 errors, registry behavior, analyzer manifest valid.

# Constraints

- Local artifacts only — zero network, zero boto3 usage.
- Pattern library must be data (JSON/YAML/python table), not hardcoded if-chains, so it can grow.
- No invented error classes — each pattern maps to a real, commonly observed error shape; cite source in pattern metadata where known.
- PT-BR titles/explanations for findings (docs language), English technical terms preserved.
