- Owner: Edgar (§01.7 enumerates requirements; §10 security NFRs apply).
- Decided at grill: implementer = Devin in-session; review→archive gated by owner acceptance; docs/CLI PT-BR, code/commits English.
- Problem: analyzers will read arbitrary local files (logs, SQL, metadata) — path traversal, oversized inputs, and leaked credentials in evidence are the top risks.
- Out of scope: auth/authz, network security, prompt-injection defense for LLM (Cycle 05), encryption at rest.
- Review failure: path traversal possible, file size limit bypassable, AWS key patterns survive into evidence excerpts.
- Riskiest assumption: default-allow of absolute paths is unsafe — policy = files must resolve inside cwd tree or be explicitly allowlisted.
- Smallest acceptable: `safe_resolve(path, allowed_roots)`, `read_input_file` (size + binary guards), `redact_secrets(text)`, `sanitize_log_text` (control chars) — all tested with hostile inputs.

# Context

Phase 01.7 security foundation. The tool reads untrusted artifacts; every evidence excerpt it stores must be sanitized and secret-redacted. Read-only by default; never execute content-derived commands.

# Acceptance Criteria

- `core/security/paths.py`: `safe_resolve()` rejects `..` escapes outside allowed roots, symlinks escaping roots, non-files, non-existent paths — with clear domain errors. Absolute paths outside cwd allowed only when the caller passes them explicitly as allowed roots (CLI arg case — documented).
- `read_input_file()` enforces `max_file_size_bytes` from config, detects binary input and rejects or safely decodes (configurable, default reject with message).
- `core/security/redact.py`: pattern library covering AWS access keys (AKIA/ASIA), AWS secret keys in context, generic tokens (Bearer, `token=`, `password=`, `secret=`), private key blocks, connection strings with credentials. Replacement marker documented (e.g. `«redacted:aws-access-key»`).
- `sanitize_log_text()`: strips ANSI/control chars (keeps \n\t), normalizes encoding errors, truncates to configured excerpt length with truncation marker.
- Public helper `sanitize_evidence_excerpt(text)` = sanitize + redact, the single entry point analyzers use.
- Security test suite (`tests/security/`): traversal payloads (`../`, absolute, symlink, NUL), oversized files, binary files, each redaction pattern positive/negative cases, malformed/empty inputs.
- No `subprocess`, `os.system`, `eval`, `exec` anywhere in `src/` — enforced by a test that scans source.

# Constraints

- Primitives only — no analyzer/CLI wiring beyond making the helpers importable.
- No runtime dependency additions (stdlib re/os/pathlib only).
- Redaction must be conservative: prefer over-masking near-certain secrets over leaking.
