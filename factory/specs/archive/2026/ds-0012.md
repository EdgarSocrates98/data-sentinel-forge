# Context

Phase §4 (02.2). Turns logs and metrics into usable evidence. Two halves: a CloudWatch connector (same `[aws]` extra, same read-only enforcement) and pure-local analysis modules (`analyzers/cloudwatch/` + `diagnostics/`) that also work on exported log/metric files offline.

# Acceptance Criteria

- `connectors/aws/cloudwatch_logs.py`: read events from configurable log groups/streams, temporal windows, pagination, ordered events, filter patterns, correlation by run id, volume caps, permission-error handling. Must not assume a fixed Glue log group (document `--log-group`/`--log-stream` + security-config custom groups).
- `connectors/aws/cloudwatch_metrics.py`: fetch metric statistics for Glue/CloudWatch namespaces with official names/dimensions/units (verified against AWS docs); missing/disabled metrics yield absent results — never fabricated series.
- `analyzers/cloudwatch/log_parser.py`: specialized parsers for Py4JJavaError, SparkException, AnalysisException, OOM, ExecutorLostFailure, FetchFailedException, TaskKilled, PermissionDenied, AccessDeniedException, S3 errors, Glue Catalog errors, Iceberg exceptions, SQL parse errors — preserving message + stack context; unknown lines pass through unparsed but timestamped when possible.
- `diagnostics/correlation.py`: groups correlated events (chained exceptions, same stage/task/executor, temporal proximity) and distinguishes **primary error** from secondary/cascade errors — an executor OOM must not classify each subsequent stage failure as an independent root cause. Explicit, documented heuristic rules (no ML).
- `MetricObservation` internal model (namespace, metric_name, dimensions, timestamp, value, unit, statistic, source, quality) preserving cumulative/gauge/delta semantics — no indiscriminate summation across semantics.
- `diagnostics/timeline.py`: incident timeline of normalized events — every entry traces to an observed timestamp; illustrative ordering like the prompt's example.
- `CloudWatchLogAnalyzer` analyzer-protocol implementation wiring parser+correlation into findings/evidence with source stream:timestamp references.
- Security: volume caps enforced, raw logs not persisted unless explicitly requested, evidence origin recorded, secrets redacted through existing sanitize path.
- Fixture-based tests: multi-stream logs, chained exceptions, throttling fixture, missing metrics, incomplete logs — plus Stubber tests for both connectors.

# Constraints

- Connector half requires `[aws]`; analyzer/parser/timeline/correlation halves must run fully offline on exported artifacts.
- No invented metric values or timestamps — absence is data.
- Document CloudWatch query cost caveat in the guide.
