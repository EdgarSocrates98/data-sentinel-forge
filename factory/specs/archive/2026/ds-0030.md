# Grill Gate

- Decidido na sessão de grill (aplica a ds-0030..ds-0039):
  1. Interop = **import-only agora** (Doctor bundle -> Sentinel; export fica
     trivial depois, contratos simétricos).
  2. Avaliação = **Doctor real** instalado em venv separada, executado de
     verdade nos cenários (nunca mockado como tendo capacidades ausentes).
  3. Findings importados = **Finding interno + provenance imported**
     (Evidence DECLARED do producer externo; nunca auto-CONFIRMED).
  4. Exec mode = **CLI/venv separada** — prova independência real.
- Restrições herdadas: AWS real BLOCKED sem credenciais; CI remota com
  billing bloqueado; Doctor repos são read-only nesta execução.

# Context

§1 (auditoria código-real de Data Sentinel, Forge Doctor Data, Forge Doctor
API), §1.4 (matriz), checkpoint A.

# Acceptance Criteria

- Audit doc com SHA dos 3 repos, inventário de capacidades por inspeção de
  código (não README): analyzers, contratos, conectores, knowledge rules,
  CLI, export formats, persistência, testes
- Matriz de sobreposição classificando: Sentinel-only, Doctor-only,
  overlap justificável, overlap redundante, gaps dos dois lados
- Formatos públicos de saída do Doctor identificados (JSON/report/bundle?)
  com exemplos reais coletados como fixtures locais (cópia read-only)
- docs/cycles/cycle-03.1-baseline.md (reuso do formato C03)

# Constraints

- Determinístico-first; nenhum LLM no caminho de execução.
- Offline-capable: núcleo funciona sem AWS e sem o ecossistema Forge.
- Integrações opcionais — nenhuma dependência obrigatória nova.
- Não remover funcionalidades válidas (Cycles 01-03 sem regressão).
- Não modificar repositórios externos (Doctor é somente-leitura para auditoria e fixtures exportadas).
- Sem operações cloud mutáveis; sem downloads automáticos de bundles.
- Findings importados preservam proveniência — nunca viram CONFIRMED automaticamente.
- Nenhum ganho declarado sem medição reproduzível.
