# Context

Phase 01.5 requires configuration with precedence: CLI args > env vars > project config > user config > safe defaults. Profiles from §6 (economy, balanced, deep, offline) must exist as first-class config.

# Acceptance Criteria

- `SentinelConfig` Pydantic model covering: analysis profile, log level, max file size bytes, evidence redaction on/off, store path, output format default.
- Precedence implemented and tested: `DATA_SENTINEL_*` env vars override project config (`data-sentinel.toml` discovered upward from cwd) which overrides user config (`~/.config/data-sentinel/config.toml`) which overrides defaults; CLI args handled at the command layer (documented, tested at CLI spec).
- The 4 profiles (`economy`, `balanced`, `deep`, `offline`) defined with documented per-profile defaults (token/tool-call budgets may be placeholders for Cycle 05, marked as such).
- Validation errors produce domain exceptions with clear PT-BR messages (what's wrong, which source).
- Secret-looking keys are redacted in `config show` output and in `repr`/`model_dump(mode="redacted")` — never persisted in plaintext by the tool itself.
- Config discovery reports which files were found/used (`config show --sources` or equivalent in model).
- Unit tests: each precedence layer, env override, invalid values rejected, redaction, profile selection, missing files tolerated.

# Constraints

- No CLI command implementation here — config loading library only (ds-0008 wires the command).
- No writes to config files in this spec.
- Do not log or echo secret values anywhere.
