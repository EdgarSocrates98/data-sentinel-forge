# Acceptance Criteria

- Golden fixture suite covering the §10.2 list (20 cases): Glue job success/failure/permission-error, Spark OOM/fetch-failure/executor-lost/sort-merge-join/broadcast-join/AQE-plan/skew, SQL multi-JOIN/CTE/CROSS-JOIN/duplicate-key-risk, missing statistics, incomplete logs, malformed plan, CloudWatch throttling, credentials missing, sensitive-info-in-logs. Each fixture declares: entrada, resultado esperado, achados esperados, **achados proibidos**, evidências esperadas, limitações esperadas — asserted by a golden-test harness.
- Security tests (§10.3): path traversal, oversized files, sensitive data in logs, injection-looking log content, malicious SQL text, permission errors, auth failures, parameter manipulation, unexpected AWS responses. No SQL/code extracted from input is ever executed.
- `tests/benchmarks/`: measured on documented hardware (record cpu/platform/python in output JSON): SQL parse time, plan analysis time, log analysis time, memory consumption, scaling vs artifact size, simulated AWS call counts, report-generation overhead. Results committed under `docs/evidence/` — real numbers only.
- `tests/e2e/` implementing §11 scenarios A–E end-to-end through the CLI/orchestrator: A (local Spark SQL w/ 4 JOINs → report), B (physical plan → tree/strategies/limitations), C (mocked Glue failure → timeline/primary-exception/diagnosis), D (missing evidence → inconclusive + what would help), E (high-volume 4-table JOIN risk). Each asserts the scenario's numbered steps.
- Optional AWS integration tests gated behind an explicit env flag (`DATA_SENTINEL_AWS_TESTS=1`), skipped by default, never using prod, never calling mutating APIs.
- CI updated to run the new test dirs; pytest-benchmark (or timing harness) added to dev deps if used.
