# Context

Phase §5 (02.3). Deterministic parser + analyzer for Spark physical/logical plans — text EXPLAIN outputs, not a live Spark session. New `SourceType.SPARK_PLAN` artifact.

# Acceptance Criteria

- `analyzers/spark/plans/` package: `PlanNode` (node_id, operator, parent_id, children, expressions, statistics, source_span, raw_text, metadata) and `ExecutionPlan` (plan_id, format, spark_version, roots, nodes, edges, warnings, source) — internal models preserving hierarchy/order.
- Parser for EXPLAIN simple/extended/formatted/cost and DataFrame.explain textual output; detects format from content; tolerant of Spark 3.3/3.4/3.5 differences in fixtures; does not assume Glue/Databricks/OSS formats identical.
- Operator recognition for at least: Scan, Filter, Project, HashAggregate, SortAggregate, Sort, Exchange, BroadcastExchange, BroadcastHashJoin, SortMergeJoin, ShuffledHashJoin, CartesianProduct, BroadcastNestedLoopJoin, Repartition, Coalesce, Union, Window, AdaptiveSparkPlan. Unknown operators become typed "unknown" nodes, never abort analysis.
- Analyses flag *investigation candidates*: expensive-looking shuffles, multiple exchanges, sorts, joins, wide scans, missing filters, possible computation duplication, cross joins, costly aggregations, potentially inappropriate broadcast, excessive repartition. An `Exchange`/`SortMergeJoin` existing is NOT itself a finding — severity requires corroborating signal (statistics, repetition, absence of filters).
- AQE: detect AdaptiveSparkPlan; when initial/adaptive/final sections are distinguishable, report which plan level each finding came from; an initial plan is never conclusive evidence of final execution.
- Statistics (rowCount, sizeInBytes, cardinality estimates, partition info, cost) captured with provenance labeled estimated/declared/observed — propagated into findings' confidence.
- `SparkPlanAnalyzer` implements the analyzer protocol; emits plan-tree diagnostics (operators found, priority operators, shuffle points, join strategies, stats, parse warnings, bottleneck hypotheses, evidence, next steps).
- Robustness fixtures + tests: variable formatting, unknown operators, truncated lines, partially corrupted plans, deep trees, repeated nodes, AQE variants, missing metadata, large plans. Parser is pure-Python — no eval/dynamic execution.
- Finding statuses: CONFIRMED only for syntactic certainties (operator present); hypotheses about cost stay PROBABLE/POSSIBLE.

# Constraints

- Offline only — no Spark session, no JVM, no network.
- Findings must cite node ids + source spans as evidence.
- Do not claim a plan-level problem is a runtime problem — limitations state plan ≠ execution.
